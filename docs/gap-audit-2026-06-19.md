## Critical Blockers

### B-1 — `__init__.py` version frozen at 1.0.0 while `pyproject.toml` is at 1.3.0

**What was planned/expected:** `src/bearings/__init__.py.__version__` should match the authoritative version in `pyproject.toml`. The `create_app()` function reads `__version__` to populate the OpenAPI `info.version` field, and `scripts/check_version_alignment.py` (a pre-commit hook and CI gate) compares `pyproject.toml` to `docs/openapi.json` and exits non-zero on a mismatch.

**What is missing:** `__init__.py` line 9 still reads `__version__ = "1.0.0"`. `pyproject.toml` line 3 is `version = "1.3.0"`. The OpenAPI spec emitted by the running app therefore also reports `1.0.0`. `check_version_alignment.py` prints `MISMATCH` and exits 1, which means pre-commit and CI are broken on every commit until this is corrected.

**Source:** `src/bearings/__init__.py:9`, `pyproject.toml:3`, `docs/openapi.json` (info.version), `scripts/check_version_alignment.py`

**What was planned/expected:** The reply-actions route accepts a transform instruction, calls an LLM advisor callable, and returns the rewritten content. The module architecture isolates the LLM call behind a swappable `run_transform` module-level reference so it can be injected at startup.

**What is missing:** `run_transform` defaults to `_stub_run_transform` (line 104), which raises `NotImplementedError`. Neither `cli/serve.py` nor `web/app.py` ever replaces it. Any production call to the endpoint raises HTTP 500. Additionally, `insert_follow_up` is advertised in the OpenAPI contract but is unconditionally `inserted = False` (lines 221–226) — a permanent no-op with no wiring path.

**Source:** `src/bearings/web/routes/reply_actions.py:87–104, 221–226`; `src/bearings/web/app.py` (no `run_transform` injection found); `docs/openapi.json:7563`

### M-10 — Token aggregation ignores legacy `input_tokens` — 2382 migrated messages show 0 tokens

**What was planned/expected:** Inspector metrics tab should show accurate token counts for all sessions, including those migrated from v0.17.x.

**What is missing:** `db/messages.py:get_token_totals()` (lines 445–461) aggregates only `executor_input_tokens` and `executor_output_tokens`. The migration script (`migrate_v0_17_to_v0_18.py:510–548`) writes `executor_input_tokens=NULL` for every migrated message while preserving the original counts in the legacy `input_tokens`/`output_tokens` columns. The live database has 2382 assistant-role rows where `executor_input_tokens IS NULL AND input_tokens IS NOT NULL`. All migrated sessions display 0 tokens in the Inspector. The fix is `COALESCE(executor_input_tokens, input_tokens, 0)`.

**Source:** `src/bearings/db/messages.py:445–461`; `scripts/migrate_v0_17_to_v0_18.py:510–548`; live DB confirmed 2382 affected rows
